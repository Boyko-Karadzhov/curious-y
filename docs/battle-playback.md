# Settled battles and local playback

Start freezes the army, towers, Keep HP, opponent rotation, reward and rules version. The learning Edge function assigns the request ID as the battle identity and derives a uint32 seed from the command's reserved server entropy. It runs the complete fixed-step simulation, then commits the final battle and campaign progress through the existing revision-checked command transaction. A retry retrieves the same committed receipt; it cannot award a second win. Victory Gold remains uncollected until Collect.

The browser reconstructs time zero with `replayBattle` using the persisted configuration and maximum Keep HP. `advanceBattle` is the exact function used for both server settlement and browser simulation. Combat currently makes no random choices: spawn rotation and targeting ties are deterministic. Future random combat decisions must consume the stored seed in a deterministic order and ship with an appropriate rules version; neither wall time nor `Math.random()` may affect combat.

`BattlePlayback` accumulates animation-frame time into complete fixed steps (currently 50 ms of viewing time). Canvas movement interpolates between known simulation positions for one step; it does not extrapolate during new battles. Wallet refreshes do not rewind the battle. Hidden tabs pause viewing, and session storage remembers only the viewing position. The account-level hook continues playback when the user switches to Learn or Castle. Reloading resumes from the saved position by reconstructing from frozen inputs. Missing viewing storage can only replay the animation, never lose or duplicate account progress.

While viewing, the UI overlays the local battle and hides the settled campaign win. At completion or Skip battle it reveals the latest trusted state, including the saved result. Skip is local and cannot turn the result into a defeat. The local simulation never submits fighter state, damage, an outcome or rewards. New battles make no periodic server requests and require no result request at the end. The old tick/catch-up path is retained only for battles saved without a replay identity before this change.

No schema migration is required: the complete endpoint, frozen configuration, identity and seed live in the existing battle JSON. Deploy the learning Edge function and frontend together. Validation covers full-state parity across army compositions and stages, frame timing, server JSON transport, atomic settlement/retry/collection, offline playback, refresh, reload, account reset and hidden tabs.
